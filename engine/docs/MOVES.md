# Moves: one row per skill family

What every skill does once cast, family by family. The plan and lane rules are in MOVES-PLAN.md; table fields and units in FORMATS-SKILLS.md ("Motion parameters", "Units"); the game's guide text (`Data/Menu/mb01..05_en.ssb`) is the spec — quote it, don't invent.

## How it's built (Phase 0, 2026-09-26)

- `crates/pd_game/src/moves/mod.rs` — the **registry**: `behaviour_of(def)` picks a `Behaviour` (AuraParticle / Melee / Shoot / Guard / NotBuilt) from the skill's table record; `launch(kind, …)` turns a `Shoot` into `Shot`s. Table units (`SIM_TICKS_PER_TABLE_TICK`, `TABLE_DIST`, `TABLE_SPEED`, `HOMING_PER_POINT`) and field helpers (`motion()`, `param(k)`, `blast_radius()`, `pierces()`, `ignores_defence()`, `ignores_walls()`) live here.
- One module per family: `melee.rs`, `shell.rs`, `parabola.rs`, `arc.rs`, `crawl.rs`, `fall.rs`, `area.rs`, `barrier.rs`. Pure functions, no Bevy, deterministic.
- `combat.rs` owns the dispatch and the shared sim state: casting, the projectile list (`Shot`: velocity, gravity, homing, flat steering, arc curve, floor-following, delay, life, blast, through-walls), sub-stepped hit tests (fast shells can't tunnel), blasts, **set areas** (`Area`: warning countdown, pulses, timer / sensor / remote trigger, open-sky and floor-only checks), guards (`ActiveGuard`) and STR vs DEF (`barrier::resolve`). Attacks from above/below (Rain, Hole) pass `from = None` to `strike`, so only an all-round guard covers them.
- `SkillDef.raw` holds the whole table record, so a family lane needs no loader change.
- Events for the renderer: `Hit`, `Blocked { broken }`, `Burst { pos }` (exploding shot or area going off → hit effect there). `fx.rs` also draws each area's own slot-1 effect while it's set, and a faint disc while a Hole/Rain still shows where it will land.

**Adding a family (Phase 1 lane):** new `moves/<family>.rs` with `from_def` + `launch` (or a guard/other behaviour) and unit tests → one `ShotKind`/`Behaviour` variant + one line in `behaviour_of` + one in `launch`. If the family needs new sim state (areas that go off later: Hole, Rain, mines), add it to `combat.rs` in the same shape as `projectiles` — coordinate, it's a shared file. Add a row below with evidence; show a `--demo --loadout` burst.

## Cast timing (moves track M3, 2026-09-27)

Every cast now fires at its own action-table row's `fire_tick` instead of a
flat `CAST_TICKS`, and holds the caster for the row's own clip length
instead of a flat guess (`combat::Combat::action_row`, `clip_hold_ticks`;
docs/FORMATS-SKILLS.md "Action table"). Rows are kept on `Combat`
(`action_rows`, set once at startup from `skills.json` by
`main.rs::load_action_rows`), not on `SkillDef` itself, so building a
`SkillDef` by hand elsewhere in the crate (tests, the front end's
stand-ins) doesn't need to change. A skill with no row set (most test
fixtures) falls back to the old flat `CAST_TICKS`, so existing behaviour is
unchanged unless a row is actually supplied. Clip lengths come from each
side's own converted model when it's in the cache
(`combat::clip_ticks_from_glb`, read once at match start — no Bevy, no
`gltf` crate, just the glTF JSON chunk's own accessor `max`), else a small
built-in table of the values PROGRAM-RE.md's per-handler timelines give
(`default_clip_table_ticks`). A hit before the fire tick still cancels the
pending shot (unchanged rule, now checked against the row's own tick
instead of the flat one). Mid-air casts use the row's air side (s13) per
PROGRAM-RE.md's dispatch rule (s40 = 1/3, or 2 while airborne).

## Which casts hold the fighter still (lane caststill, 2026-10-01)

Read from `PDUWP.exe` (`decomp_all.c`; the dropped arguments by the castrules
lane's capstone reads), checked against the footage `Orb Collect & Aura
Consumed.mp4` (frames in `~/.pdtools/footage/caststill/`, not committed).

**The rule is per skill, from its action row, not per capsule colour.**

- A press runs `0x140258180`, which calls `0x14025a3e0` to start the cast. For a
  row that is valid and names a real clip (row word w38 = `anim_id` != 0) the
  fighter enters **state 10 (ground) / 11 (air)**, with the state timer = the
  clip's length in frames (`0x140259d10`, minus the combo offset w48 = 0). The
  state's handler `0x14025bd40` only turns the body toward the captured aim; it
  never reads the stick and never moves the body (state 11 also zeroes `vy` and
  skips gravity, `0x140254590`). So the fighter is **held for the whole clip**
  (`len + 1` program ticks; 40 frames = 82 sim ticks for SPE_POWER_UP /
  SPE_HEAL; castpose lane 2026-10-02: LIVE takes_full, 268 of the roster takes end exactly press + len + 1; before that fix ours held `len`), whatever the capsule colour, in the air or on the ground. Only a
  held charge freezes the timer longer (`0x14025bd40` tail). A hit starts
  another state (`0x140258690`) and so ends the hold into the reaction.
- A row whose clip is **0 (`WAIT0`)**, or no row at all, makes `0x14025a3e0`
  return 0 and `0x140258180` fire the skill at once (`0x1402626d0`) **with no
  state change**: nothing holds the body. These are, of the 342 table records
  with id <= 340: Skywalk 51, Levitate 56, Return 57, Surprise Attack 58,
  Retreat 60, Optical Camo 115, Copy 205, Recollection 206, Void 235, Jump 239,
  257, Demon's Wing 292, Charge 304 (13), **and the Aura Particle**, program
  record 0: its row 343 is valid, clip 0, fire tick 0, only a rumble entry. Every
  other roster skill (329) is held for its clip: all 29 environment crystals
  (ENV_SET), the 8 green Status skills on SPE_POWER_UP (Speed Up, Heat, Stimulate,
  Tiger's Strength, Trance, Lightning Speed, Acquisition, Meditation) and the 2 on
  SPE_RESET, the Specials on SPE_HEAL / SPE_POWER_UP, the defences, every attack
  and erase.
- **Capturing a capsule changes no state** (`0x1402517c0` -> `0x140261a00`,
  `0x140262670`): the program does not hold the fighter for a capture of any
  colour.

**What ours does.** Every real-clip cast holds for the clip (matches). **The
instant skills above hold nobody either** (lane instants, 2026-10-01, replacing the
80-tick hold the first caststill pass kept for them): a row naming `WAIT0` makes
`Combat::cast_from` queue the fire for the press itself (`fire_instants`), with no
cast state, no pivot drop and no turn; the cast sound and effect still start
(`cast_seq`), and Level / Aura are paid in the press. The row's fire tick (20 for
Optical Camo, Void, Demon's Wing) is not used, as in the program (`0x140258180`
calls `0x1402626d0` as soon as `0x14025a3e0` returns 0). Recollection (206) and
Copy (205) resolve at the press to the copied skill and cast on ITS row. **The Aura Particle use
and every capture hold nobody**: `Combat::cast_from` pays Level +1 and returns before
any cast state, the capture arm only sets the slot. This is settled by a live trace
of the PC original (moverec, 2026-10-01, four runs, stick held forward through the
use: 1.85 u per program tick before, at and after the press, state "run", Level 3 ->
4, sound 89; `~/.pdtools/moverec/takes/000_Aura_Particle_held_stick_trace.csv`,
`pilot_run2.log`) and agrees with the program read above. The traces logged no
capture (`capsule_touched` false in every take), so the capture half rests on the
read. History: an owner-directed 12 -> 80 -> 46-tick hold (and a 79-tick capture lock,
FRONTIER O2) existed earlier on 2026-10-01 and were removed. The green glow after a
use (`AURA_GLOW_TICKS`, sounds 89 + 90) is render-only and unchanged.
Tests: `a_cast_with_a_real_clip_holds_the_fighter_for_the_whole_clip`,
`a_row_naming_clip_zero_fires_in_the_press_and_holds_nobody`,
`an_instant_cast_in_the_air_does_not_freeze_the_body`,
`recollection_and_copy_cast_the_copied_skills_row_not_their_own`,
`an_instant_effect_on_the_opponent_lands_s65_program_ticks_after_its_fire_tick`,
`bundled_strength_sums_the_equipped_skills_of_the_same_kind_field`,
`using_an_aura_particle_holds_nobody_and_fires_at_once`,
`capturing_a_capsule_holds_nobody`,
`an_aura_particle_use_does_not_pause_the_aura_refill`,
`the_instant_skills_are_the_ones_whose_row_names_no_clip`.

**Instant effects on the opponent land late (lane instants).** A non-attack skill with
target kind 0 and motion 4 (Purify, Fairy Ring, Quantum Decay, Armaros, Chill Breeze,
Blessed Rain, Return to Nature, Quantum Amp, Vicious Balance...) is an object whose
countdown `FUN_140265ea0` sets to s65 and `FUN_140265f50` spends before applying the
effect: 25 program ticks for most, 5 for Frighten, 0 for the crystal erasers. Ours
queues it in `Combat::take_effect` (`delayed_effects`) and lands it `2 x s65` sim ticks
after the fire tick (30 Hz program, 60 Hz sim); the hit event and sound come with the
landing. STR rule 26 (bundled skills) sums s46 over the occupied buttons whose s10 equals
the skill's s46 (`0x140274990`), not by name.

## Hit reactions and knock-down (rebuilt 2026-09-27, hit-reactions lane)

**Corrects the 2026-09-26 reading below**: s57/s58/s59 are **light/medium/heavy**, not "standing/air" — PROGRAM-RE.md "Hit reactions" (`FUN_14024fd80`). A hit picks a row of the hit-reaction table (`cache/skills.json` top-level `"reactions"`, loaded into the sim as plain data, `Combat::set_reaction_rows`/`reaction_rows`, same pattern as the action table):

- **In the air → row 27 (a knock-down) always**, regardless of s57-s59 (s61, the "air" field, is 0 on every skill, so it always resolves to 27). `Combat::pick_reaction`.
- **On the ground, by the damage the victim took in the last 3 s (this hit included, `Combat::recent_damage`, 180 sim ticks): < 3 → s57 (light), 3-4 → s58 (medium), ≥ 5 → s59 (heavy)**.
- Whether the picked row is actually a knock-down comes from the row's own **kind** (`reaction_kind::KNOCKDOWN` = 5), read from the table — not a fixed list of ids (`Combat::reaction_is_knockdown`; a hard-coded fallback list only backs up tests that don't load a table).
- **s62** (`Combat::hits_downed`/`only_hits_downed`): a bitmask of states the attack can touch (0 reads as bit 1, normal). Backdraft Bullet (6 = downed bits, no normal bit) only lands on a downed target; Gravity Press/Geyser Impact (7) land on both. Pursuit/Sky Pursuit aren't gated by s62 at all — they always carry reaction 24, the fixed **pinned** kind (7), which `only_hits_downed` also checks directly ("Pursuit/Sky Pursuit check the down state themselves", PROGRAM-RE.md).
- **s60** plays a second reaction once the hit's Add effect actually lands (skill erased, aura drain, status up/down, reset, confusion, binds) — `Combat::attack_extra`.

**Knock-down physics** (`Combat::start_knockdown`/`step_knockdown_flight`): launch velocity from the row's own `launch_speed`/`launch_angle` (only 50° and 90° appear in the table; their sin/cos are precomputed constants, no runtime trig) along the hit direction, using the program's own knock-down gravity (0.12 u/(1/30 s)² = 108 u/s² — now the same number the movement lane found for ordinary jump/fall gravity too) and real ground collision to land — not a fixed flight-time guess. After landing: 120 sim ticks (2 s) lying, then 60 (1 s) getting up (`KNOCK_LYING_TICKS`/`KNOCK_GETUP_TICKS`), a small ground slide (15%/tick decay) throughout. Getting up starts `POST_GETUP_INVULN_TICKS` (150 sim ticks = 2.5 s) of blinking invulnerability — no skill's s62 sets bit 8 (the only thing that could still reach a player then), so this reads as full invulnerability, not just "downed-only" gating.

- Which side the hit arrived from (`HitDir`: front/right/back/left, `hit_direction`) picks the reaction's clip out of the row's own chain (`Combat::reaction_clip`, kind-dependent: four-way, front/back, or a knock-down's front/back launch pose) — `main.rs`'s `clip_for` for `Motion::Hit`/`Motion::Blown`. The lying/get-up poses aren't in the row (`Combat::lying_clip`/`getup_clip`): front/back by `hit_dir`, and a bigger launch (Tornado) uses the "L" BLOW_LAND clip against an ordinary "M" one — the size split isn't confirmed in the program, just the only number the table gives us.
- Falling out of the arena: 3 damage on respawn (guide).
