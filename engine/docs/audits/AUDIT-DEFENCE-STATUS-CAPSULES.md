# Audit: defence, erase, status, special, environment, capsules vs the original (2026-09-30, cloud, read-only)

Document-and-code audit only. Nothing was run; no game data or Ghidra export was available. It compares what `PROGRAM-RE.md` (phases 2 and 3), `FORMATS-SKILLS.md`, `MOVES.md`, `MOVES-PLAN.md` and `CAPSULE-VISUALS.md` say the original does with what our code does (`pd_game/src/combat.rs`, `moves/barrier.rs`, `moves/status.rs`, `moves/erase.rs`, `moves/special.rs`, `moves/environment.rs`, `moves/effects.rs`). Nothing here is a new finding about the program: every "program read" cell quotes a doc, and "check on PC" items are questions for Ghidra. Style follows `MOVEMENT-AUDIT.md`.

Verdicts: **MATCH** (code follows the doc's program read), **ADDED BY US** (a rule the program read does not contain), **DIFFERS** (program read says otherwise), **UNKNOWN** (no program read, or the read is marked uncertain). Line numbers are `combat.rs` unless a file is named. Units: the program ticks at 30 Hz, we run 60 Hz; `moves::table_ticks` (`moves/mod.rs:45`) multiplies table ticks by 2.

## Summary of the biggest gaps

1. **Guards resolve differently in the core loop.** A block does not use up DEF and does not end the guard; the program drains DEF and ends the guard 5 ticks after any block. The guard goes up at the button press, not at the action row's fire tick. Front guards are a 180 degree half-plane, not a 13 u disc 5 u in front. Guard time is s46 x 2 sim ticks, not about (s46 - 1) x 2. Defence DEF ignores s48 (per-use change). Any damage to the holder drops the guard (ours).
2. **Per-kind ignore lists are mostly missing** (Absorb ignores blasts/Rain/Tornado/mines/around-self, Brush the same, About Face only lists motions). Only "Absorb vs melee" is coded.
3. **Status system is a different model.** The program keeps numbered status slots (value, amount, timer) with caps and a hit-clears rule; we keep a Vec of stacking modifiers plus ad hoc timers. Status ids 11, 12, 16, 20, 22, 23, 31 (and 29, 30, 34, 35, 37) are either unbuilt or mapped by name guess. "Inverted controls" (our s51 = 37) may actually be the program's 90 degree stick rotation (status 35).
4. **Capsules / Aura**: respawn is 900 sim ticks (15 s) vs the program's 420 + 15 ticks (14.5 s); Aura refill is flat 1 point/s vs `max(0.25, 1.25 - Aura/10)` per s, and it is not paused during casts or dodges; pickup is "stand + press a button" in code but footage in `CAPSULE-VISUALS.md` says "the player walks into the orb".
5. **Doc-vs-code contradictions** are listed in section 9 (GAME.md says Level starts at 1 and capsules come every 2 s; MOVES.md still says guard time and Course size are unconfirmed; AGENTS.md says "all defence kinds" built).
