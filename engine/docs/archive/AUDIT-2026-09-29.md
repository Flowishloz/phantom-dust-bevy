# What is actually missing — a code-truth audit (2026-09-29)

Laurence asked for an audit that reads the code instead of the planning docs,
because I had twice recommended building something that already existed on the
strength of a stale `ROADMAP.md`. This file is that audit. **Every line below
was checked against the source**, and where a doc disagrees with the code, the
code wins and the doc is called out.

Reproduce the skill numbers with:

```
cargo test -p pd_game skill_coverage_audit -- --nocapture
```

The test is a measurement, not a gate. It asserts nothing, always passes, and
prints the distribution of all 397 skills across `moves::behaviour_of`'s arms.

## `GAME.md` "Not built yet" — checked

- **HUD aura meter segments** — not built. Confirmed absent.
- **2-v-2 and resuscitation** — not built. No `resusc`/`2v2`/`team` code.
- **Online play** — not built, as agreed.
- **Gamepad remapping** — not built. No `remap` code.
- **Deck-menu art and status icons** — not built as original art; the deck
  builder exists (`frontend/builder.rs`, `frontend/arsenals.rs`) with no icons.
- **"Camera still pulls in very close when a fight hugs a wall"** — ⚠️ **the
  camera collision is implemented** (`main.rs:1584-1597`: raycast, pull in
  immediately, ease back out). What Laurence is seeing is the `(hit - 3.0).max(4.0)`
  floor — the camera is *allowed* to come within 4 units of the head, which on
  a tight corridor reads as a close-up. That is a **tuning** problem, not a
  missing feature. The fix is the constant, not new code.
- **Footsteps** — built (`2de8ffb`); the sound gap is documented in
  FORMATS-AUDIO.md.

## Things the docs got factually wrong

- **ROADMAP item 4's Psycho Kinesis candidate filter** is documented as
  "class 2 … exclude floor sections kind 23 / 26 / 28 / 48 / 58". The code's
  `STRUCTURAL_KINDS` is **`[6, 23, 26, 28, 48]`** (`props.rs:44`) — it excludes
  kind **6** and does *not* exclude **58**. 58 is handled separately, by the
  scripted-kind guard above it. Worth reconciling; the doc's list is wrong.
- **`moves/mod.rs`'s `motion::OBJECT` arm** carries the comment "stage objects
  aren't simulated". That was true when written and is **false now** — props are
  simulated and thrown. The arm still routes through `Shell::from_def`, which
  happens to be correct because `combat.rs` intercepts `OBJECT` before launch
  and handles the throw itself. The comment is misleading and should be fixed
  when that file is next touched.
- **ROADMAP "Next" items 4, 5, 6 are all complete** but still listed as pending.

## What this changes

The three items I recommended earlier — props-as-sim-entities, camera
pull-in, and (implicitly) "what the ROADMAP says is next" — are **two already
done and one a tuning tweak**. That is the whole reason this audit exists: the
planning docs had drifted far enough from the code that reading them produced
three wrong recommendations in one sitting.

The real remaining work, in order of what a player would notice:

1. **The 14 placeholder skills** (ids listed above) — the only genuine
   "skill family not built" gap, and it is 3.5% of the roster, not all of it.
2. **Capsule glow sprites** — the one explicitly-acknowledged missing visual.
3. **Camera close-in tuning** — a constant, not a feature.
4. **Destructible stages** (st04 `yuka`, st06 collapse) — needs OA01/OE00 decode.
5. **Anti-aliasing** — already researched and sized (RESEARCH-LIGHTING.md), a
   settings toggle, nothing to decide.
6. **Hit-stop / KO slow-mo** — render-side, cheap, and it is what makes combat
   feel like it has weight.
7. Sound: the 20% wet footstep and the capsule sounds, both parked pending a
   frontier model for the bank/variant resolution.
